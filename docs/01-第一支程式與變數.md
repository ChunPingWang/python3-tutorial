# 第 1 章：第一支程式與變數

> 🎬 **情境**
> 阿宏遞給你一張皺皺的紙條：「今天第一杯，珍珠奶茶，大杯，65 元，付現。你先幫我記到電腦裡。」
> 就這樣。一筆訂單，四個資訊。看起來簡單到不需要寫程式——但這正是最好的起點：
> **我們要搞懂「電腦要怎麼記住一件事」。**

---

## 1.1 😩 土法煉鋼：只會 print 的世界

你剛學會 `print`，於是你這樣寫：

```python
print("珍珠奶茶")
print("大杯")
print(65)
print("付現")
```

執行結果：

```
珍珠奶茶
大杯
65
付現
```

**問題來了**：阿宏說「幫我算一下，如果賣 3 杯是多少錢？」

你做不到。因為 `print` 只是「把東西顯示在螢幕上」，說完就忘。
電腦沒有**記住**那個 65，它只是把字印出來而已。就像你對著空氣念了一個數字，念完就沒了。

> 🔍 **`print` 的真正角色**
> `print` 不是「執行」，而是「給人看」。程式內部的運算完全不需要 `print` 也能進行。
> 初學者常以為「沒 print 出來就是沒跑」，其實程式跑得好好的，只是它沒義務跟你報告。

---

## 1.2 🧪 先寫測試：把期待寫下來

在寫任何程式之前，先問自己：**「我希望做完之後，什麼事情會是真的？」**

阿宏要的是：能記住品項、杯型、價格，而且能拿出來用。寫成測試：

```python
# 🔴 此時下面這些名字通通還不存在,執行一定紅燈
assert 品項 == "珍珠奶茶"
assert 杯型 == "大杯"
assert 單價 == 65
assert 單價 * 3 == 195      # ← 這就是阿宏問的「3 杯多少錢」
```

執行它：

```
NameError: name '品項' is not defined
```

🔴 **紅燈。很好。** 紅燈不是失敗，紅燈是「我的需求已經寫清楚了，而且電腦確認我還沒做到」。

> 🔍 **為什麼要先讓它紅一次？**
> 因為一個「從來沒紅過」的測試，你不知道它到底有沒有在檢查東西。
> 見過太多人寫了測試、一執行就綠燈，開心得不得了——結果測試裡有個手滑的 typo，它根本什麼都沒測。
> **先看到紅燈，才證明這個測試是活的。**

---

## 1.3 💡 解法：變數

變數就是**「幫一個值取名字，讓它留在記憶體裡」**。

```python
品項 = "珍珠奶茶"
杯型 = "大杯"
單價 = 65
付款方式 = "現金"
```

現在再跑一次剛才的測試：

```python
assert 品項 == "珍珠奶茶"
assert 杯型 == "大杯"
assert 單價 == 65
assert 單價 * 3 == 195
print("🟢 全部通過")
```

```
🟢 全部通過
```

🟢 **綠燈。** 而且阿宏的問題也順手回答了：`單價 * 3` 就是 195。

### `=` 不是「等於」，是「取名字」

這是初學者第一個大坑。

```python
單價 = 65        # 讀作:「把 65 這個值,取名叫 單價」
單價 == 65       # 讀作:「單價 是不是等於 65?」→ 回答 True 或 False
```

| 符號 | 名稱 | 做什麼 | 回傳 |
| --- | --- | --- | --- |
| `=` | 賦值 | 把右邊的值綁到左邊的名字上 | 不回傳東西 |
| `==` | 比較 | 問左右兩邊是否相等 | `True` 或 `False` |

`assert` 後面幾乎一定是 `==`，因為你是在**問問題**，不是在命名。

> ⚠️ 寫成 `assert 單價 = 65` 會直接語法錯誤：
> ```
> SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?
> ```
> Python 3.10 之後的錯誤訊息很貼心，會直接告訴你猜測的原因。**請養成讀錯誤訊息最後一行的習慣。**

### 變數可以改名字指向的東西

```python
單價 = 65
單價 = 70        # 阿宏漲價了
assert 單價 == 70
```

變數不是箱子，是**名牌**。你把名牌從 65 上面撕下來，貼到 70 上面。原本的 65 沒人要了，Python 會自動回收。

## 1.4 型別：值的種類

阿宏又問：「把價格跟品項黏起來給我看。」你試了：

```python
print(品項 + 單價)
```

```
TypeError: can only concatenate str (not "int") to str
```

⚠️ 這是新手最常見的錯誤之一。翻譯成人話：**「字串只能跟字串相加，你給我一個整數。」**

因為 Python 裡每個值都有**型別**：

```python
print(type("珍珠奶茶"))   # <class 'str'>   字串,文字
print(type(65))          # <class 'int'>   整數
print(type(65.5))        # <class 'float'> 浮點數,有小數點
print(type(True))        # <class 'bool'>  布林,只有 True / False
print(type(None))        # <class 'NoneType'> 空值,代表「沒有東西」
```

| 型別 | 中文 | 例子 | 什麼時候用 |
| --- | --- | --- | --- |
| `str` | 字串 | `"珍珠奶茶"`、`'大杯'` | 任何文字。電話號碼、訂單編號也要用 str！ |
| `int` | 整數 | `65`、`-3`、`0` | 杯數、價格（不含小數的錢） |
| `float` | 浮點數 | `65.5`、`0.9` | 折扣率、重量、平均值 |
| `bool` | 布林 | `True`、`False` | 是不是會員、有沒有加珍珠 |
| `None` | 空值 | `None` | 還沒填、查不到、沒有結果 |

> 🔍 **為什麼電話號碼要用字串？**
> 因為 `0912345678` 存成整數會變成 `912345678`（開頭的 0 不見了），
> 而且你永遠不會拿兩個電話號碼相加。**判斷準則：這個值會不會拿來做數學運算？不會的話就用字串。**

### 型別轉換

```python
str(65)        # '65'      → 轉成字串
int("65")      # 65        → 轉成整數
float("65")    # 65.0      → 轉成浮點數
int(65.9)      # 65        → 直接砍掉小數,不是四捨五入!
```

所以剛才那行要寫成：

```python
print(品項 + " " + str(單價) + " 元")     # 可以,但很醜
```

第 2 章會教你優雅一百倍的寫法（f-string）。

> ⚠️ `int("六十五")` 會炸掉：`ValueError: invalid literal for int() with base 10: '六十五'`。
> 型別轉換不是萬能翻譯，它只認得格式正確的東西。第 11 章會教你怎麼優雅地接住這種錯誤。

## 1.5 變數命名：程式是寫給人看的

```python
# 😩 三個月後的你會恨死現在的你
a = "珍珠奶茶"
b = 65
c = 3
d = b * c

# 🙂 好多了
品項名稱 = "珍珠奶茶"
單價 = 65
數量 = 3
小計 = 單價 * 數量
```

**規則（Python 語法強制的）**

- 只能用英文字母、數字、底線 `_`、以及中文等 Unicode 字元
- 不能用數字開頭：`2杯 = 5` ❌
- 不能用保留字：`class`、`if`、`for`、`return`、`import` 等 35 個
- 區分大小寫：`單價` 和 `單價 ` 是兩個不同的名字（注意空白！）

**慣例（不強制，但整個 Python 世界都這樣做）**

| 種類 | 寫法 | 例子 |
| --- | --- | --- |
| 一般變數、函式 | 小寫 + 底線（snake_case） | `total_price`、`is_member` |
| 常數（不會變的值） | 全大寫 | `TAX_RATE = 0.05` |
| 類別（第 10 章） | 大寫開頭（PascalCase） | `Order`、`MenuItem` |

> 🔍 **教材用中文變數名，實際工作也可以嗎？**
> Python 3 技術上完全支援，本教材前幾章刻意用中文，是為了讓你把注意力放在**概念**而不是背英文單字。
> 但**正式專案請用英文**：一來套件、錯誤訊息、同事都是英文，二來某些老舊工具遇到非 ASCII 會出狀況。
> 第 6 章開始，教材會逐步換成英文命名，帶你自然過渡。

## 1.6 註解與說明

```python
# 這是單行註解,# 後面到行尾 Python 完全無視

單價 = 65  # 也可以放在程式後面

"""
這是多行字串,常拿來寫比較長的說明。
放在函式或檔案開頭時,它有個正式名字叫 docstring(說明文件),
第 7 章你會知道它甚至可以「變成測試」。
"""
```

⚠️ **不要寫廢話註解**：

```python
單價 = 65   # 把 65 指定給單價     ← 完全沒資訊量
單價 = 65   # 大杯珍奶,2026 年 9 月調漲後價格  ← 這才有用
```

好註解回答 **why**（為什麼這樣做），程式碼本身已經說明了 **what**（做了什麼）。

## 1.7 ⚠️ 本章常見錯誤總表

| 錯誤訊息 | 意思 | 怎麼修 |
| --- | --- | --- |
| `NameError: name 'x' is not defined` | 用了沒定義的名字 | 檢查拼字；Jupyter 裡檢查那格有沒有執行過 |
| `SyntaxError: invalid syntax` | 語法寫錯 | 看錯誤指的那一行，常是 `=`/`==` 搞混、缺冒號、括號沒關 |
| `TypeError: can only concatenate str...` | 字串和數字相加 | 用 `str()` 轉換，或用 f-string（第 2 章） |
| `ValueError: invalid literal for int()` | 轉換的字串內容不合法 | 檢查來源資料 |
| `IndentationError: unexpected indent` | 行首多了空白 | 頂格寫；Python 的縮排是有意義的（第 3 章） |

> 🔍 **讀錯誤訊息的方法**：**從最後一行往上讀。**
> 最後一行告訴你「發生什麼錯」，上面的 `File "...", line N` 告訴你「在哪裡」。
> 中間那一大堆（traceback）是呼叫過程，初學階段先跳過沒關係。

## 1.8 📌 本章速記

```python
# 變數 = 幫值取名字
品項 = "珍珠奶茶"      # str  文字

是會員 = True         # bool 真假

# = 是命名,== 是提問

# 型別轉換

```
