# 第 10 章：類別與物件 —— 把資料和行為綁在一起

> 🎬 **情境**
> 阿宏的訂單越來越複雜：品項、杯型、甜度、冰塊、加料、數量、會員、備註。
>
> 你的函式簽名變成這樣：
>
> ```python
> def 結帳(品項, 杯型, 甜度, 冰塊, 加料, 數量, 是會員, 備註): ...
> ```
>
> 然後小美呼叫時寫成 `結帳("珍奶", "大杯", "半糖", "少冰", None, 2, True, "")`——
> 她把甜度和冰塊寫反了，程式照跑，客人拿到全糖去冰。

---

## 10.1 😩 土法煉鋼：參數地獄

```python
# 八個參數,順序錯了沒人知道
結帳("珍奶", "大杯", "半糖", "少冰", "珍珠", 2, True, "不要吸管")

# 用字典?好一點,但沒有任何保護
訂單 = {"品項": "珍奶", "杯形": "大杯"}    # ← 打錯字「杯形」,程式不會報錯
訂單["價格"]                             # KeyError,因為根本沒這個鍵
```

字典的問題：

1. **打錯欄位名不會報錯**，等到取用時才爆
2. **不知道有哪些欄位**，編輯器無法自動補全
3. **資料和行為分開**：算價格的函式在別的地方，你得自己記得要呼叫它

## 10.2 🧪 先寫測試：我希望怎麼用它？

```python
# 🔴 全紅
訂單 = Order(品項="珍珠奶茶", 杯型="大杯", 數量=2, 是會員=True)

assert 訂單.品項 == "珍珠奶茶"
assert 訂單.單價 == 65            # 自己知道去查菜單
assert 訂單.小計 == 130           # 自己會算
assert 訂單.應付 == 117           # 自己知道會員打折
assert "珍珠奶茶 x2" in str(訂單)  # 自己知道怎麼印出來
```

看出差別了嗎？**資料不再是死的**。訂單自己知道怎麼算價格、怎麼呈現自己。
這就是物件導向的核心概念：**把「資料」和「處理這份資料的行為」放在一起。**

## 10.3 💡 `class` 基礎

```python
class Order:
    """一筆訂單。"""

    def __init__(self, 品項, 杯型, 數量=1, 是會員=False):
        self.品項 = 品項            # self.xxx = 這個物件自己的資料(屬性)
        self.杯型 = 杯型
        self.數量 = 數量
        self.是會員 = 是會員

    def 小計(self):                 # 方法:這個物件會做的事
        return MENU[self.品項][self.杯型] * self.數量
```

```python
訂單 = Order("珍珠奶茶", "大杯", 數量=2)     # 建立一個物件(實例)
print(訂單.品項)         # 讀屬性
print(訂單.小計())       # 呼叫方法
```

### 名詞對照表

| 名詞 | 意思 | 類比 |
| --- | --- | --- |
| **類別 class** | 藍圖、模子 | 「訂單」這個概念 |
| **實例 instance / 物件 object** | 用藍圖做出來的東西 | 阿宏今天的第 37 筆訂單 |
| **屬性 attribute** | 物件的資料 | 這筆訂單的品項是珍奶 |
| **方法 method** | 物件會做的事 | 這筆訂單算得出小計 |

### `self` 是什麼？

**`self` 就是「這個物件自己」。**

```python
訂單.小計()              # 你這樣寫
Order.小計(訂單)         # Python 實際上這樣執行 ← self 就是 訂單
```

三條規則：

1. **每個方法的第一個參數都要寫 `self`**（名字是慣例，但請照做）
2. **呼叫時不用傳 `self`**，Python 自動帶入
3. **要存取自己的屬性一定要加 `self.`**

```python
def 小計(self):
    return 數量 * 單價          # ✖ NameError!這兩個名字不存在
    return self.數量 * self.單價  # ✔
```

### `__init__`：建立物件時自動執行

```python
訂單 = Order("珍珠奶茶", "大杯")
#              ↓
# Python 自動呼叫 Order.__init__(訂單, "珍珠奶茶", "大杯")
```

`__init__` 的工作就是**把參數存成屬性**。它不需要 `return`（也不能 return 東西）。

## 10.4 特殊方法（dunder methods）

名字前後有兩個底線的方法叫 dunder（double underscore），它們讓你的類別融入 Python 的語法。

```python
class Order:
    def __init__(self, 品項, 數量=1):
        self.品項 = 品項
        self.數量 = 數量

    def __str__(self):                     # print(訂單) 時用
        return f"{self.品項} x{self.數量}"

    def __repr__(self):                    # 在 Notebook 直接打變數名時用,除錯用
        return f"Order(品項={self.品項!r}, 數量={self.數量})"

    def __eq__(self, other):               # 訂單A == 訂單B 時用
        return (self.品項, self.數量) == (other.品項, other.數量)

    def __len__(self):                     # len(訂單) 時用
        return self.數量
```

| dunder | 觸發時機 | 為什麼重要 |
| --- | --- | --- |
| `__init__` | 建立物件 | 必備 |
| `__repr__` | 除錯顯示 | **強烈建議寫**，沒寫的話你會看到 `<Order object at 0x10f...>` |
| `__str__` | `print()` | 給人看的版本；沒寫會退回用 `__repr__` |
| `__eq__` | `==` | **測試需要它**！沒寫的話兩個內容相同的訂單會被判定為不相等 |

> 🔍 **`__eq__` 和測試的關係**
> 沒有 `__eq__` 時，`assert 訂單A == 訂單B` 比較的是「是不是同一個記憶體位址」，
> 所以永遠是 `False`。你只好寫成：
> ```python
> assert 訂單A.品項 == 訂單B.品項
> assert 訂單A.數量 == 訂單B.數量      # 有 8 個欄位就寫 8 行
> ```
> 定義了 `__eq__`，一行 `assert 訂單A == 訂單B` 就搞定。
> **「好不好測試」再一次告訴你該怎麼設計。**

## 10.5 💡 `dataclass`：少寫 80% 的樣板

上面那些 `self.x = x` 和 `__repr__`、`__eq__`，其實都是機械性的樣板。
Python 3.7 之後有更好的寫法：

```python
from dataclasses import dataclass, field

@dataclass
class Order:
    品項: str
    杯型: str = "中杯"
    數量: int = 1
    是會員: bool = False
    加料: list[str] = field(default_factory=list)   # ⚠️ 可變預設值要這樣寫!

    def 小計(self) -> int:
        return MENU[self.品項][self.杯型] * self.數量
```

`@dataclass` 自動幫你產生 `__init__`、`__repr__`、`__eq__`。

```python
訂單 = Order("珍珠奶茶", "大杯", 數量=2)
print(訂單)      # Order(品項='珍珠奶茶', 杯型='大杯', 數量=2, 是會員=False, 加料=[])
訂單 == Order("珍珠奶茶", "大杯", 數量=2)     # True!
```

⚠️ **可變預設值的陷阱又來了**（第 6 章）：
`加料: list = []` 會讓所有訂單共用同一個清單。必須用 `field(default_factory=list)`。

### 常用選項

```python
@dataclass(frozen=True)     # 唯讀,建立後不能改 → 可以當字典的鍵、執行緒安全
@dataclass(order=True)      # 自動產生 <、> 等比較方法,可以排序
@dataclass(slots=True)      # 省記憶體(3.10+)
```

> 🔍 **建議：資料為主的類別一律用 `dataclass`。**
> 只有當你需要複雜的初始化邏輯時，才手寫 `__init__`。
> 少寫的每一行樣板，都是少一個出錯的機會。

## 10.6 屬性 vs 方法：`@property`

```python
訂單.小計()        # 方法,要加括號
訂單.小計          # 屬性,不用括號
```

用 `@property` 可以把「算出來的東西」偽裝成屬性：

```python
@dataclass
class Order:
    品項: str
    杯型: str = "中杯"
    數量: int = 1
    是會員: bool = False

    @property
    def 單價(self) -> int:
        return MENU[self.品項][self.杯型]

    @property
    def 小計(self) -> int:
        return self.單價 * self.數量

    @property
    def 應付(self) -> int:
        return round_half_up(self.小計 * 0.9) if self.是會員 else self.小計
```

```python
訂單.小計        # 130  不用括號!而且永遠是即時計算的
訂單.數量 = 3
訂單.小計        # 195  自動跟著變
```

**什麼時候用 `@property`？**

| 用 property | 用方法 |
| --- | --- |
| 很快（幾乎瞬間） | 要花時間（查資料庫、打 API） |
| 沒有副作用 | 會改變東西 |
| 概念上是「這個物件的一個特徵」 | 概念上是「這個物件做的一個動作」 |

`訂單.小計` 讀起來像特徵 ✔；`訂單.送出訂單()` 是動作，一定要用方法。

## 10.7 繼承：什麼時候該用（以及大多數時候不該用）

```python
@dataclass
class 外送訂單(Order):          # 繼承 Order 的所有東西
    外送費: int = 50

    @property
    def 應付(self) -> int:
        return super().應付 + self.外送費      # super() = 「父類別的版本」
```

```python
訂單 = 外送訂單("珍珠奶茶", "大杯", 數量=2)
訂單.小計        # 130  ← 繼承來的
訂單.應付        # 180  ← 自己覆寫的
```

> ⚠️ **初學者最常見的錯誤：濫用繼承。**
>
> 繼承的正確條件是「**B 是一種 A**」（外送訂單**是一種**訂單 ✔）。
> 不是「B 需要用到 A 的功能」—— 那應該用**組合**：
>
> ```python
> # ✖ 錯:訂單不「是一種」印表機
> class Order(印表機): ...
>
> # ✔ 對:訂單「有一個」印表機
> @dataclass
> class Order:
>     印表機: 印表機
> ```
>
> **實務準則：先用組合，真的出現「是一種」關係時才用繼承。**
> 深層繼承（超過兩層）幾乎總是設計失誤的訊號。

## 10.8 🧪 測試類別

```python
def test_一般訂單的小計():
    訂單 = Order("珍珠奶茶", "大杯", 數量=2)
    assert 訂單.小計 == 130

def test_會員訂單自動打九折():
    訂單 = Order("珍珠奶茶", "大杯", 數量=2, 是會員=True)
    assert 訂單.應付 == 117

def test_內容相同的兩筆訂單相等():
    assert Order("珍珠奶茶") == Order("珍珠奶茶")      # 靠 dataclass 的 __eq__

def test_修改數量後小計自動更新():
    訂單 = Order("珍珠奶茶", "大杯")
    訂單.數量 = 3
    assert 訂單.小計 == 195                           # 靠 @property
```

### 測試類別的三個要點

1. **每個測試自己建立物件**，不要共用（共用會讓測試互相影響）
2. **測「行為」，不要測「內部實作」**
   ```python
   assert 訂單.應付 == 117        # ✔ 測行為
   assert 訂單._快取價格 == 130    # ✖ 測內部,一重構就壞
   ```
3. **`__eq__` 讓斷言變一行**

> 🔍 **「不要測私有屬性」是很重要的紀律。**
> 測試應該像「使用者」一樣使用你的類別。如果測試需要偷看內部，
> 代表你要嘛測錯東西，要嘛類別的公開介面設計得不夠好。

## 10.9 什麼時候**不**需要類別

初學者學會 class 之後很容易什麼都做成類別。**不要。**

| 情況 | 用什麼 |
| --- | --- |
| 只有資料，沒有行為 | `dataclass` 或字典 |
| 只有行為，沒有狀態 | **函式就好** |
| 一堆函式想「整理在一起」 | **模組**（第 8 章），不是類別 |
| 資料 + 針對該資料的行為 | ✔ 類別 |

```python
# ✖ 不必要的類別
class 計算機:
    def 加(self, a, b):
        return a + b

# ✔ 函式就好
def 加(a, b):
    return a + b
```

**判斷法：如果你的類別沒有 `self.xxx`（沒有狀態），它就不該是類別。**

## 10.10 📌 本章速記

```python
from dataclasses import dataclass, field

@dataclass
class Order:
    品項: str                                   # 必填
    數量: int = 1                                # 有預設值
    加料: list[str] = field(default_factory=list)  # ⚠️ 可變預設值要這樣

    @property                                   # 算出來的「特徵」,不用括號
    def 小計(self) -> int:
        return 單價 * self.數量

    def 送出(self) -> None:                      # 「動作」用方法
        ...

# 手寫版
class Order:
    def __init__(self, 品項):      # 建立時自動執行
        self.品項 = 品項            # self = 這個物件自己
    def __repr__(self): ...        # 除錯顯示 ← 一定要寫
    def __str__(self): ...         # print 用
    def __eq__(self, other): ...   # == 用 ← 測試需要它

# 繼承(少用)
class 外送訂單(Order):
    def 應付(self): return super().應付 + 50

# ⚠️ 準則
# 沒有 self.xxx 的類別 → 該是函式
# 「B 需要 A 的功能」→ 用組合,不要繼承
# 測行為,不要測私有屬性
```
