## 9.1 😩 土法煉鋼：寫死路徑

網路上你會看到這種程式碼：

```python
f = open("C:\\Users\\Amy\\Desktop\\訂單.csv")        # 🪟 只有小美能跑
f = open("/Users/rex/Desktop/訂單.csv")             # 🍎 只有你能跑
f = open("/home/ahong/orders.csv")                  # 🐧 只有阿宏能跑
```

三個問題：

1. **換一台電腦就壞**（換使用者名稱也壞）
2. **換作業系統就壞**（`\` vs `/`）
3. **無法測試**（測試機器上沒有那個檔案）

還有一個隱形殺手：

```python
路徑 = "C:\temp\new.csv"     # \t 變成 Tab、\n 變成換行!
```

## 9.2 💡 `pathlib`：從此不用煩惱斜線

**忘掉 `os.path` 和字串拼接。Python 3.4 之後，路徑就用 `pathlib.Path`。**

```python
from pathlib import Path

資料夾 = Path("資料")
檔案 = 資料夾 / "2026-09-20.csv"        # 用 / 組路徑!
```

`/` 這個運算子會自動用**當前作業系統**的分隔符號：

| 作業系統 | `Path("資料") / "訂單.csv"` 的實際值 |
| --- | --- |
| 🍎 macOS / 🐧 Linux | `資料/訂單.csv` |
| 🪟 Windows | `資料\訂單.csv` |

**你只要寫一種，Python 處理差異。**

### Path 的常用操作

```python
p = Path("資料") / "2026-09-20.csv"

# 資訊
p.name          # '2026-09-20.csv'   檔名
p.stem          # '2026-09-20'       不含副檔名
p.suffix        # '.csv'             副檔名
p.parent        # Path('資料')        上層資料夾
p.parts         # ('資料', '2026-09-20.csv')

# 判斷
p.exists()      # 存在嗎
p.is_file()     # 是檔案嗎
p.is_dir()      # 是資料夾嗎

# 轉換
p.resolve()     # 轉成絕對路徑
p.absolute()    # 同上(較不嚴謹)

# 讀寫(小檔案的快速做法)
p.write_text("內容", encoding="utf-8")
內容 = p.read_text(encoding="utf-8")

# 資料夾
Path("資料").mkdir(exist_ok=True)              # 已存在不報錯
Path("a/b/c").mkdir(parents=True, exist_ok=True)   # 連中間層一起建

# 列出檔案
list(Path("資料").iterdir())              # 直接子項目
list(Path("資料").glob("*.csv"))          # 符合樣式的
list(Path("資料").rglob("*.csv"))         # 遞迴搜尋所有子資料夾

# 刪除
p.unlink()              # 刪檔案
p.unlink(missing_ok=True)   # 不存在也不報錯
Path("空資料夾").rmdir()     # 刪空資料夾
```

### 幾個重要的「起點」

```python
Path.cwd()          # 目前工作目錄(你執行 python 的地方)
Path.home()         # 使用者家目錄(🍎 /Users/rex、🪟 C:\Users\Rex)
Path(__file__)      # 這個 .py 檔自己的位置(Notebook 裡沒有這個變數)
```

**專案裡最常用的寫法**（找到專案根目錄，不管從哪裡執行都對）：

```python
# 在 drinkshop/storage.py 裡
專案根目錄 = Path(__file__).resolve().parent.parent
資料目錄 = 專案根目錄 / "data"
```

> 🔍 **`Path.cwd()` 和 `Path(__file__)` 的差別很重要：**
> - `Path.cwd()` = 「你在哪裡執行 python」→ 會變
> - `Path(__file__)` = 「這個程式檔放在哪」→ 固定
>
> 要找專案裡的資料檔，**一律用 `__file__` 推算**。用 `cwd()` 的程式，
> 從別的目錄執行就會找不到檔案。

## 9.3 ⚠️⚠️ 編碼：中文使用者的頭號地雷

```python
open("訂單.csv")        # ← 這行在 Windows 上讀中文會壞掉
```

**為什麼？** 因為 `open()` 不指定 `encoding` 時，會用「系統預設編碼」：

| 系統 | 預設編碼 |
| --- | --- |
| 🍎 macOS / 🐧 Linux | UTF-8 |
| 🪟 Windows（繁中）| **cp950（Big5）** |
| 🪟 Windows 10 1903+ 開啟 UTF-8 選項 | UTF-8 |

所以你在 Mac 上寫的 UTF-8 檔案，小美在 Windows 上用預設編碼讀，會得到：

```
UnicodeDecodeError: 'cp950' codec can't decode byte 0xe7 in position 0
```

或更可怕的——**不報錯，但內容變成亂碼**（`ç­è¨` 這種）。

### ✅ 鐵則：每一次讀寫文字檔，都明確寫 `encoding="utf-8"`

```python
open(路徑, "r", encoding="utf-8")
open(路徑, "w", encoding="utf-8")
路徑.read_text(encoding="utf-8")
路徑.write_text(內容, encoding="utf-8")
```

**沒有例外。** 這一個習慣可以省掉你未來 90% 的中文亂碼問題。

> 🔍 **Python 3.15 起，預設編碼將改為 UTF-8**（PEP 686），但在那之前、以及面對舊系統時，
> 明確指定仍然是唯一安全的做法。而且明確寫出來，讀程式的人也不用猜。

### ⚠️ 給 Excel 看的 CSV：`utf-8-sig`

如果檔案要給人用 Excel 開，用 `utf-8` 會讓中文變亂碼（Excel 猜錯編碼）。
解法是加上 BOM：

```python
with open("報表.csv", "w", encoding="utf-8-sig", newline="") as f:
    ...
```

`utf-8-sig` 會在檔案開頭放一個看不見的記號，Excel 看到就知道「這是 UTF-8」。

## 9.4 ⚠️ 換行符號：另一個跨平台差異

| 系統 | 換行符號 |
| --- | --- |
| 🍎🐧 | `\n`（LF） |
| 🪟 | `\r\n`（CRLF） |

Python 的文字模式預設會幫你自動轉換（叫做 universal newlines），所以**大多數時候你不用管**。

**但寫 CSV 是例外**：

```python
import csv

# ✔ 正確:一定要加 newline=""
with open("報表.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["品項", "數量"])
```

**不加 `newline=""` 的話，Windows 上每一列之間會多一個空行。**
這是 csv 模組文件明確要求的寫法，請無腦照做。

## 9.5 `open()` 與 `with`

```python
# ✖ 不好:忘記關檔
f = open("訂單.csv", encoding="utf-8")
內容 = f.read()
f.close()          # 如果中間出錯,這行永遠不會執行,檔案就一直開著

# ✔ 正確:with 會自動關檔,即使中間爆炸也一樣
with open("訂單.csv", encoding="utf-8") as f:
    內容 = f.read()
```

**永遠用 `with`。** 這個語法叫 *context manager*，用途就是「確保收尾一定會做」。

### 模式

| 模式 | 意思 | 檔案不存在 | 檔案已存在 |
| --- | --- | --- | --- |
| `"r"` | 讀取（預設） | ❌ 報錯 | 讀 |
| `"w"` | 寫入 | 建立 | ⚠️ **清空** |
| `"a"` | 附加 | 建立 | 加在後面 |
| `"x"` | 獨佔建立 | 建立 | ❌ 報錯（防止覆蓋） |
| `"rb"` / `"wb"` | 二進位 | | 圖片、影片用，**不要加 encoding** |

⚠️ **`"w"` 會直接清空整個檔案。** 用錯模式導致一整天資料消失，是很常見的災難。
怕覆蓋就用 `"x"`，它會在檔案已存在時拋出 `FileExistsError`。

### 三種讀法

```python
with open(路徑, encoding="utf-8") as f:
    內容 = f.read()            # 整個檔案變成一個字串(小檔案)

with open(路徑, encoding="utf-8") as f:
    行們 = f.readlines()       # 變成清單,每行一個元素

with open(路徑, encoding="utf-8") as f:
    for 行 in f:               # ✔ 一行一行讀,記憶體友善(大檔案一定用這個)
        處理(行.rstrip("\n"))
```

> 🔍 **為什麼大檔案要一行一行讀？**
> `f.read()` 會把整個檔案載入記憶體。1 GB 的日誌檔會直接吃掉你 1 GB 的 RAM。
> 逐行讀則是「用多少讀多少」。**養成逐行讀的習慣，你永遠不會遇到記憶體爆掉。**

## 9.6 CSV：試算表的通用格式

```python
import csv
from pathlib import Path

路徑 = Path("訂單.csv")

# 寫入
with 路徑.open("w", encoding="utf-8", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["品項", "杯型", "金額"])       # 標題列
    writer.writerow(["珍珠奶茶", "大杯", 65])

# 讀取
with 路徑.open(encoding="utf-8", newline="") as f:
    for 列 in csv.reader(f):
        print(列)      # ['品項', '杯型', '金額'] 然後 ['珍珠奶茶', '大杯', '65']
```

⚠️ **CSV 讀進來全部是字串。** `'65'` 不是 `65`，要自己轉型。

### `DictReader` / `DictWriter`（推薦）

用欄位名稱存取，比用 `列[2]` 好懂太多：

```python
with 路徑.open("w", encoding="utf-8", newline="") as f:
    writer = csv.DictWriter(f, fieldnames=["品項", "杯型", "金額"])
    writer.writeheader()
    writer.writerow({"品項": "珍珠奶茶", "杯型": "大杯", "金額": 65})

with 路徑.open(encoding="utf-8", newline="") as f:
    for 列 in csv.DictReader(f):
        print(列["品項"], int(列["金額"]))      # 用名字取,而且記得轉型
```

**為什麼推薦 `DictReader`？** 因為別人在 CSV 中間插入一個欄位時，
用 `列[2]` 的程式會默默算錯，用 `列["金額"]` 的程式完全不受影響。

## 9.7 JSON：程式之間交換資料的標準

CSV 只能存「表格」，JSON 可以存巢狀結構（像阿宏的菜單）。

```python
import json

菜單 = {"珍珠奶茶": {"中杯": 55, "大杯": 65}}

# 寫入
with open("菜單.json", "w", encoding="utf-8") as f:
    json.dump(菜單, f, ensure_ascii=False, indent=2)

# 讀取
with open("菜單.json", encoding="utf-8") as f:
    菜單 = json.load(f)
```

⚠️ **`ensure_ascii=False` 一定要加**，否則中文會被存成 `"\u73cd\u73e0"` 這種看不懂的東西。
（還是讀得回來，只是人看不懂，而且檔案變大。）

⚠️ `indent=2` 讓檔案有排版，方便人閱讀和用 git 比對差異。

| 函式 | 做什麼 |
| --- | --- |
| `json.dump(物件, 檔案)` | 寫進**檔案** |
| `json.dumps(物件)` | 轉成**字串**（多一個 s = string） |
| `json.load(檔案)` | 從**檔案**讀 |
| `json.loads(字串)` | 從**字串**讀 |

### CSV vs JSON 怎麼選

| | CSV | JSON |
| --- | --- | --- |
| 結構 | 只能平面表格 | 可巢狀 |
| Excel 能開 | ✔ | ✖ |
| 型別 | 全部是字串 | 保留數字/布林/null |
| 適合 | 交易紀錄、報表 | 設定檔、菜單、API |

## 9.8 🧪 測試會碰檔案的程式

這是本章最重要的一節。**檔案 I/O 是最難測的東西**，因為它有副作用。

### ❌ 錯誤做法

```python
def test_存檔():
    存檔("/tmp/test.csv", 資料)          # 🪟 Windows 沒有 /tmp
    assert Path("/tmp/test.csv").exists()
    # 而且測試結束後垃圾檔留在硬碟上
```

### ✅ 正確做法一：pytest 的 `tmp_path`

```python
def test_存檔(tmp_path):                  # pytest 自動注入
    檔案 = tmp_path / "訂單.csv"           # 每個測試一個全新的暫存目錄
    存檔(檔案, [("珍珠奶茶", 65)])

    assert 檔案.exists()
    assert "珍珠奶茶" in 檔案.read_text(encoding="utf-8")
    # 測試結束後 pytest 自動清理,跨平台
```

### ✅ 正確做法二：標準庫的 `tempfile`（不用 pytest 也行）

```python
import tempfile
from pathlib import Path

with tempfile.TemporaryDirectory() as 暫存:
    檔案 = Path(暫存) / "訂單.csv"
    存檔(檔案, 資料)
    assert 檔案.exists()
# 離開 with 就自動刪除整個目錄
```

### ✅ 最佳做法：讓大部分程式「根本不碰檔案」

```python
# ✖ 難測:計算和存檔混在一起
def 產生日報表並存檔(訂單, 路徑):
    總額 = sum(o["金額"] for o in 訂單)
    路徑.write_text(f"總額:{總額}", encoding="utf-8")

# ✔ 好測:拆成純函式 + 薄薄一層 I/O
def 產生日報表(訂單) -> str:              # 純函式,三行測試搞定
    總額 = sum(o["金額"] for o in 訂單)
    return f"總額:{總額}"

def 存檔(內容: str, 路徑: Path) -> None:   # 只有這個需要碰硬碟
    路徑.write_text(內容, encoding="utf-8")
```

現在 95% 的邏輯可以用純粹的 `assert` 測：

```python
def test_日報表內容():
    assert 產生日報表([{"金額": 65}, {"金額": 45}]) == "總額:110"
```

只剩一個超簡單的 `存檔` 需要用 `tmp_path` 測。

> 🔍 **這就是第 8 章說的「把副作用推到邊界」。**
> 你會發現：**為了讓程式好測試而做的設計，剛好就是好的設計。**
> 這是 TDD 最大的附加價值 —— 它不只是在抓 bug，它在改善你的架構。

## 9.9 ⚠️ 跨平台檢查清單

寫完程式，用這張表檢查一遍：

| 檢查項 | ❌ 不要 | ✅ 要 |
| --- | --- | --- |
| 組路徑 | `"資料/" + 檔名`、`os.path.join` | `Path("資料") / 檔名` |
| 絕對路徑 | `"C:\\Users\\..."`、`"/home/..."` | `Path(__file__).parent`、`Path.home()` |
| 編碼 | `open(p)` | `open(p, encoding="utf-8")` |
| 寫 CSV | `open(p, "w")` | `open(p, "w", newline="", encoding="utf-8")` |
| 暫存檔 | `/tmp/x.csv` | `tempfile` 或 pytest `tmp_path` |
| 換行 | `"\r\n"` 或 `"\n"` 寫死 | 交給 Python 處理 |
| 大小寫 | 假設檔名不分大小寫 | 🪟 不分、🍎🐧 **分**，一律當成有分 |
| 執行指令 | `os.system("ls")` | `subprocess.run([...])`，或根本不要呼叫系統指令 |

> ⚠️ **檔名大小寫特別容易中招**：
> 你在 Mac 上寫 `open("Data.csv")` 而實際檔名是 `data.csv`，Mac 預設不分大小寫，**能跑**。
> 部署到 Linux 伺服器，立刻 `FileNotFoundError`。這是超級常見的上線事故。
