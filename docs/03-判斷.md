# 第 3 章：判斷 —— 讓程式做選擇

> 🎬 **情境**
> 阿宏推出會員制度，規則越加越多：
>
> 1. 會員打 9 折
> 2. 大杯加 10 元、中杯不加
> 3. 消費滿 200 再折 20
> 4. 「員工價」一律 40 元，不再套用任何折扣
>
> 你昨天寫的 `單價 * 數量` 在第一條規則就死了。**價格不再是固定的，它取決於情況。**

---

## 3.1 😩 土法煉鋼：每種情況寫一個變數

```python
一般價 = 65
會員價 = 59
大杯加價 = 10
員工價 = 40
# ...然後呢?
```

寫到這裡你就卡住了：**你有四個變數，但客人只會是其中一種。**
你需要的不是「四個答案」，而是**「根據情況挑一個答案」的能力**。

這就是 `if`。

---

## 3.2 🧪 先寫測試：把規則變成表格

規則一多，用文字描述一定會漏。**先把規則攤成測試，你會立刻發現自己漏想了什麼。**

```python
# 🔴 全紅
assert 計算價格(基本價=65, 杯型="中杯", 是會員=False, 是員工=False) == 65
assert 計算價格(基本價=65, 杯型="大杯", 是會員=False, 是員工=False) == 75   # +10
assert 計算價格(基本價=65, 杯型="中杯", 是會員=True,  是員工=False) == 59   # 9 折,四捨五入
assert 計算價格(基本價=65, 杯型="大杯", 是會員=True,  是員工=False) == 68   # (65+10)*0.9=67.5→68
assert 計算價格(基本價=65, 杯型="大杯", 是會員=True,  是員工=True)  == 40   # 員工價蓋過一切
```

寫這五行的過程中，你被迫回答了三個阿宏沒說清楚的問題：

| 模糊的地方 | 你必須問清楚 |
| --- | --- |
| 大杯加價是在折扣**前**還是**後**？ | 先加價再打折（(65+10)×0.9） |
| 會員又是員工怎麼算？ | 員工價優先，不再打折 |
| 67.5 怎麼收？ | 四捨五入 → 68 |

> 🔍 **這就是 TDD 最被低估的價值。**
> 一般人寫程式是「先寫，遇到問題再問」；TDD 是「先把問題攤開，問完再寫」。
> 後者省下的返工時間，遠超過寫測試花的時間。

## 3.3 💡 `if` / `elif` / `else`

```python
if 條件:
    # 條件成立時做這些
elif 另一個條件:
    # 上面不成立、這個成立時做這些
else:
    # 全都不成立時做這些
```

三個語法重點，初學者每個都會踩：

### 1️⃣ 冒號 `:` 不能忘

```python
if 是會員          # ❌ SyntaxError: expected ':'
if 是會員:         # ✔
```

### 2️⃣ 縮排就是範圍（Python 的靈魂）

其他語言用 `{ }` 標示範圍，Python 用**縮排**。

```python
if 是會員:
    價格 = 59          # 縮排 → 屬於 if 裡面
    print("會員價")    # 縮排 → 也屬於 if 裡面
print("謝謝惠顧")       # 沒縮排 → 不管是不是會員都會執行
```

**規範：一層用 4 個空格。不要用 Tab，不要混用。**
混用 Tab 和空格會得到 `TabError: inconsistent use of tabs and spaces in indentation`，
而且肉眼看起來一模一樣，是新手最痛苦的除錯經驗之一。（Jupyter 和 VS Code 預設都幫你轉成空格，別去改它。）

### 3️⃣ `elif` 是「否則如果」，而且會短路

```python
分數 = 85
if 分數 >= 90:
    等級 = "A"
elif 分數 >= 80:      # 只有在 >= 90 不成立時才檢查
    等級 = "B"
elif 分數 >= 70:
    等級 = "C"
else:
    等級 = "D"
```

⚠️ **順序很重要。** 如果把 `>= 70` 寫在最前面，85 分會變成 C，因為它先命中了。
**寫多層 `elif` 時，從最嚴格的條件開始寫。**

⚠️ 對比一下「全部都用 `if`」的錯誤版本：

```python
if 分數 >= 90: 等級 = "A"
if 分數 >= 80: 等級 = "B"      # 90 分的人會在這裡被改成 B!
if 分數 >= 70: 等級 = "C"      # ...然後又被改成 C
```

`if` 是「每個都檢查」，`elif` 是「命中一個就不再往下」。

## 3.4 比較與布林運算

### 比較運算子（結果都是 `True` / `False`）

```python
65 == 65      # True   等於
65 != 70      # True   不等於
65 > 60       # True   大於
65 >= 65      # True   大於等於
"珍珠" in "珍珠奶茶"   # True   包含
"椰果" not in "珍珠奶茶"  # True  不包含
```

Python 有個很多語言沒有的好東西：**連續比較**

```python
0 < 分數 <= 100        # 可以這樣寫!
0 < 分數 and 分數 <= 100   # 其他語言要這樣寫
```

### 邏輯運算子

| 運算子 | 意思 | 例子 |
| --- | --- | --- |
| `and` | 兩個都要成立 | `是會員 and 金額 >= 200` |
| `or` | 任一成立即可 | `是會員 or 是員工` |
| `not` | 反過來 | `not 是會員` |

⚠️ Python 用英文字 `and` / `or` / `not`，**不是** `&&` `||` `!`（那是 C/Java/JS 的寫法）。

### 真值判斷：什麼東西算「假」？

`if` 後面不一定要放比較式，可以直接放值：

```python
if 訂單清單:          # 清單裡有東西就成立
    print("有訂單")
```

**Python 認定為「假」的只有這幾種**（其他一律為真）：

```python
False, None, 0, 0.0, "", [], {}, (), set()
```

也就是：**空的、零的、None，都是假。**

```python
名字 = ""
if 名字:
    print("有名字")
else:
    print("名字是空的")      # ← 會走這裡
```

⚠️ **經典陷阱**：

```python
數量 = 0
if 數量:                  # 0 是假!
    print("有輸入數量")    # 不會執行
```

如果你真正想問的是「使用者有沒有填這個欄位」，要明確寫 `if 數量 is not None:`。

### ⚠️ `==` 和 `is` 的差別

```python
a = [1, 2]
b = [1, 2]
a == b      # True   內容一樣嗎?
a is b      # False  是同一個東西嗎?(記憶體位置相同嗎)
```

**準則：比較值用 `==`；只有跟 `None`、`True`、`False` 比較時用 `is`。**

```python
if 備註 is None:        # ✔ 正確寫法
if 備註 == None:        # ✖ 能動,但不是慣例
```

## 3.5 🟢 讓測試變綠

```python
from decimal import Decimal, ROUND_HALF_UP

員工單價 = 40
大杯加價 = 10
會員折扣 = 0.9

def 四捨五入(數值) -> int:
    return int(Decimal(str(數值)).quantize(Decimal("1"), rounding=ROUND_HALF_UP))

def 計算價格(基本價, 杯型, 是會員, 是員工):
    # 規則 4:員工價最優先,直接回傳,後面全部不做
    if 是員工:
        return 員工單價

    價格 = 基本價
    if 杯型 == "大杯":
        價格 += 大杯加價

    if 是會員:
        價格 = 四捨五入(價格 * 會員折扣)

    return 價格
```

> 🔍 **`return` 提早結束的威力**
> 「員工價蓋過一切」這條規則，用 `if 是員工: return 員工單價` 一行就解決了。
> 如果硬要寫成一個巨大的 `if/else` 巢狀結構，你會得到這種東西：
>
> ```python
> if 是員工:
>     價格 = 40
> else:
>     if 杯型 == "大杯":
>         if 是會員:
>             ...            # 縮排地獄
> ```
>
> **早點 `return`，讓後面的程式不用再操心已經處理掉的情況** —— 這個技巧叫 *guard clause*（防衛式子句），
> 是讓程式好讀的最有效技巧之一。

## 3.6 三元運算式與 `match`

### 一行的 if：三元運算式

```python
狀態 = "會員" if 是會員 else "非會員"
提袋數 = 整袋 + (1 if 剩下 else 0)      # 第 2 章那行就是這個
```

讀法：**「(結果A) if (條件) else (結果B)」**。適合簡單的二選一，巢狀之後就別用了。

### `match`（Python 3.10+）

多個「等於某個值」的分支，`match` 比一長串 `elif` 清楚：

```python
match 杯型:
    case "大杯":
        加價 = 10
    case "中杯":
        加價 = 0
    case "小杯":
        加價 = -5
    case _:                    # _ 代表「其他」
        raise ValueError(f"未知杯型:{杯型}")
```

⚠️ 需要 Python 3.10 以上。如果你的環境是 3.9，用 `elif` 或字典（第 5 章）代替。

## 3.7 ⚠️ 本章常見錯誤

| 錯誤訊息 | 原因 |
| --- | --- |
| `SyntaxError: expected ':'` | `if` 後面忘記冒號 |
| `IndentationError: expected an indented block` | `if` 底下沒有縮排的內容 |
| `IndentationError: unexpected indent` | 多縮排了 |
| `TabError: inconsistent use of tabs and spaces` | Tab 和空格混用 |
| `NameError: name 'true' is not defined` | Python 是 `True`，**大寫開頭** |
| 邏輯沒錯但結果不對 | 檢查 `elif` 順序、檢查是否該用 `elif` 卻寫成 `if` |
