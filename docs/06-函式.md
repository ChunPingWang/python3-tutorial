# 第 6 章：函式 —— 把做法包起來，只寫一次

> 🎬 **情境**
> 阿宏：「所有飲料調漲 5 元。」
>
> 你打開程式，發現「算價格」這件事你在三個地方各寫了一次：結帳畫面一次、日報表一次、會員 App 一次。
> 你改了兩處，漏了第三處。隔天阿宏發現 App 上的價格是舊的，客訴。

---

## 6.1 😩 土法煉鋼：複製貼上邏輯

```python
# 結帳畫面
價格 = 菜單[品名][杯型]
if 是會員:
    價格 = round(價格 * 0.9)

# 日報表
價格 = 菜單[品名][杯型]
if 是會員:
    價格 = round(價格 * 0.9)      # 一模一樣的六行

# 會員 App
價格 = 菜單[品名][杯型]
if 是會員:
    價格 = round(價格 * 0.85)     # ← 這裡不小心打成 0.85,而且沒人發現
```

**重複的程式碼有三個致命傷：**

1. **改一個要改 N 個**，漏掉就是 bug
2. **複製時會抄錯**，而且錯得很難發現
3. **沒辦法測試**。你要怎麼寫 `assert` 去測「散落在三個檔案裡的六行」？

> 🔍 **這點特別重要：不能被測試的程式碼，通常是因為它沒有被好好地「包起來」。**
> TDD 之所以會讓程式結構變好，就是因為「想測試它」這個念頭會逼你把邏輯抽成一個有名字、有輸入、有輸出的東西。
> 而那個東西就叫**函式**。

---

## 6.2 🧪 先寫測試：測試先決定了函式的樣子

寫測試的時候，你其實在做設計決策：

```python
# 我希望怎麼「呼叫」它?
assert price_of("珍珠奶茶", "大杯") == 65

# 會員呢?多一個參數
assert price_of("珍珠奶茶", "大杯", is_member=True) == 59

# 不存在的品項呢?我希望它...爆炸?還是回 0?
# → 決定:爆炸。因為這代表點餐系統有 bug,不該默默算成 0 元
```

光是寫這三行，你就決定了：**函式名稱、參數順序、參數名稱、回傳型別、以及錯誤處理策略**。

> 🔍 **這就是「Test-Driven **Design**」** —— TDD 的 D 有人說是 Development，也有人說其實是 Design。
> 你先站在「使用者」的角度寫呼叫方式，再回頭實作。
> 這樣寫出來的函式，介面幾乎一定比「先實作再想怎麼呼叫」好用。

## 6.3 💡 定義函式

```python
def price_of(name, size):          # def 名稱(參數):
    """回傳指定品項與杯型的價格。"""   # docstring:說明文件
    return MENU[name][size]        # return 把結果送回去
```

四個組成部分：

| 部分 | 作用 |
| --- | --- |
| `def` | 告訴 Python「我要定義一個函式」 |
| 參數 `(name, size)` | 函式需要的輸入 |
| docstring | 這個函式做什麼（第 7 章會讓它**變成測試**） |
| `return` | 把結果送回呼叫的人 |

### ⚠️ `return` 和 `print` 完全不同

這是初學者最大的混淆點：

```python
def 版本A(a, b):
    print(a + b)          # 印在螢幕上,但沒有把值交出來

def 版本B(a, b):
    return a + b          # 把值交出來

x = 版本A(1, 2)     # 螢幕印出 3,但 x 是 None!
y = 版本B(1, 2)     # 螢幕什麼都沒有,但 y 是 3 ✔

assert 版本B(1, 2) == 3      # ✔ 可以測試
assert 版本A(1, 2) == 3      # ✖ AssertionError,因為回傳 None
```

**判斷準則：如果你想對結果做任何事（計算、測試、存檔），就必須 `return`。**
`print` 只是給人看的最後一步。

> 🔍 **這也是為什麼 TDD 會改善你的程式**：
> 只要你打算寫 `assert`，你就自然會寫 `return` 而不是 `print`，
> 而 `return` 版本的函式才能被組合、被重複使用。

### 沒有 `return` 的函式回傳 `None`

```python
def 打招呼(名字):
    print(f"哈囉 {名字}")

結果 = 打招呼("阿宏")
print(結果)        # None
```

## 6.4 參數的各種形式

### 位置參數 vs 關鍵字參數

```python
def price_of(name, size, is_member=False):
    ...

price_of("珍珠奶茶", "大杯")                    # 位置參數,順序很重要
price_of("珍珠奶茶", "大杯", True)              # 可以,但 True 是什麼意思?
price_of("珍珠奶茶", "大杯", is_member=True)    # ✔ 清楚多了
price_of(size="大杯", name="珍珠奶茶")          # 用名字指定,順序就不重要了
```

⚠️ **布林參數一定要用關鍵字寫法。** `f(x, True, False, True)` 這種呼叫，三個月後沒人看得懂。

### 預設值

```python
def price_of(name, size="中杯", is_member=False):
    ...

price_of("珍珠奶茶")     # size 用預設的「中杯」
```

⚠️⚠️ **絕對不要用可變物件當預設值** —— 這是 Python 最惡名昭彰的陷阱：

```python
def 加訂單(訂單, 清單=[]):       # ✖ 災難
    清單.append(訂單)
    return 清單

print(加訂單("珍奶"))     # ['珍奶']
print(加訂單("紅茶"))     # ['珍奶', '紅茶']  ← 為什麼上一次的還在?!
```

**原因**：預設值只在「定義函式的那一刻」建立一次，之後每次呼叫都是**同一個清單**。

**正確寫法**：

```python
def 加訂單(訂單, 清單=None):
    if 清單 is None:
        清單 = []
    清單.append(訂單)
    return 清單
```

### `*args` 和 `**kwargs`

```python
def 總計(*金額們):              # 收集任意多個位置參數成 tuple
    return sum(金額們)

總計(65, 45, 120)              # 230

def 建立訂單(**欄位):           # 收集任意多個關鍵字參數成 dict
    return 欄位

建立訂單(品名="珍奶", 杯型="大杯")   # {'品名': '珍奶', '杯型': '大杯'}
```

初學階段知道看得懂就好，真正需要時自然會用到。

## 6.5 型別註記：寫給人和工具看的說明

```python
def price_of(name: str, size: str, is_member: bool = False) -> int:
    """回傳含折扣的價格(整數元)。"""
    ...
```

⚠️ **Python 不會檢查型別註記。** 你傳字串給 `name: int` 它照跑不誤。

那為什麼要寫？

1. **給人看**：不用讀完整個函式就知道要傳什麼、會拿到什麼
2. **給編輯器看**：VS Code 會自動補全、會在你傳錯時畫紅線
3. **給檢查工具看**：`mypy`、`pyright` 可以在執行前抓出型別錯誤

常用寫法：

```python
def f(x: int) -> str: ...
def g(items: list[str]) -> dict[str, int]: ...
def h(x: int | None) -> None: ...          # 可能是 int 也可能是 None(3.10+)
```

> 🔍 **型別註記和測試是互補的**：註記說「應該是什麼型別」，測試說「應該是什麼值」。
> 兩個一起用，你的函式就很難被誤用了。

## 6.6 作用域：函式裡面和外面是兩個世界

```python
稅率 = 0.05              # 全域變數

def 含稅(金額):
    結果 = 金額 * (1 + 稅率)    # ✔ 可以「讀」外面的變數
    return 結果

print(結果)      # ✖ NameError!結果 只活在函式裡面
```

**規則**：

- 函式**可以讀**外面的變數
- 函式裡面的 `x = ...` 會建立一個**只屬於函式的新變數**，不會影響外面

```python
計數 = 0

def 加一():
    計數 = 計數 + 1       # ✖ UnboundLocalError

加一()
```

Python 看到函式裡有 `計數 = `，就認定 `計數` 是區域變數，於是右邊的 `計數` 變成「還沒賦值就使用」。

**解法不是 `global`，而是改用 `return`：**

```python
def 加一(計數):
    return 計數 + 1

計數 = 加一(計數)        # ✔ 清楚、可測試
```

> ⚠️ **請把 `global` 當成最後手段。**
> 用 `global` 的函式無法單獨測試（它依賴外部狀態）、無法重複使用、debug 時你永遠不知道誰改了它。
> **好函式的定義：給它同樣的輸入，永遠得到同樣的輸出，而且不偷偷改變外面的東西。**
> 這種函式叫 *pure function*（純函式），也是最好測試的函式。

## 6.7 🟢 讓測試變綠

```python
MENU = {
    "珍珠奶茶": {"中杯": 55, "大杯": 65},
    "冬瓜檸檬": {"中杯": 40, "大杯": 45},
}
MEMBER_DISCOUNT = 0.9

def round_half_up(value: float) -> int:
    """台灣習慣的四捨五入(逢五進一)。"""
    from decimal import Decimal, ROUND_HALF_UP
    return int(Decimal(str(value)).quantize(Decimal("1"), rounding=ROUND_HALF_UP))

def price_of(name: str, size: str, is_member: bool = False) -> int:
    """回傳指定品項、杯型的價格;會員自動套用 9 折。

    品項或杯型不存在時拋出 KeyError —— 這代表點餐系統有 bug,
    不應該默默算成 0 元。
    """
    price = MENU[name][size]
    if is_member:
        price = round_half_up(price * MEMBER_DISCOUNT)
    return price
```

```python
assert price_of("珍珠奶茶", "大杯") == 65
assert price_of("珍珠奶茶", "中杯") == 55
assert price_of("珍珠奶茶", "大杯", is_member=True) == 59
print("🟢 全綠")
```

現在「調漲 5 元」只要改 `MENU` 一個地方，三個畫面同時更新。

## 6.8 一個函式該做多少事？

**一個函式只做一件事，而且名字要說得出它做了什麼。**

如果你的函式名字需要用「而且」「然後」來描述，它就該被拆開：

```python
# ✖ 名字裡有「並」 → 做了兩件事
def 計算價格並存檔(...): ...

# ✔ 拆成兩個
def 計算價格(...) -> int: ...
def 存檔(結果) -> None: ...
```

> 🔍 **好用的判斷法：這個函式好不好測試？**
> - `計算價格並存檔()` → 測試它會在你硬碟上留下檔案，很難測、很髒
> - `計算價格()` → 給輸入、比對輸出，三行測試搞定
>
> **「難測試」幾乎總是在告訴你「設計不好」。這是 TDD 送給你的免費設計警報器。**

## 6.9 📌 本章速記

```python
def 名稱(必填參數, 選填參數=預設值) -> 回傳型別:
    """說明文件。"""
    return 結果

# return vs print
return  # 把值交出去,可以被計算、被測試 ← 邏輯用這個
print   # 顯示給人看 ← 最後一步才用

# 參數
f(65, 45)                # 位置
f(name="珍奶")            # 關鍵字(布林參數一定要這樣寫)
def f(x, y=0): ...       # 預設值
def f(*args, **kwargs)   # 任意多個

# ⚠️ 陷阱
def f(清單=[]): ...       # 絕對不要!改用 =None 再在裡面建立

# 作用域
函式可以「讀」外面 / 函式裡指派不會影響外面 / 少用 global,改用 return

# 型別註記(不強制,但強烈建議)
def f(x: int, s: str = "") -> list[str]: ...
```
